# Daynote — описание первой версии

## Назначение и подтверждённые требования

Отдельное Windows-приложение для личных заметок и расписания. Название Daynote, публичный GitHub-репозиторий `97Dmitry/daynote`. Пользователь разрешил создать папку проекта, репозиторий и реализовать приложение. Данные локальные, без аккаунта и синхронизации. OneDrive используется для резервных копий, а не для рабочей базы.

Пользовательский пример: утренний созвон в 09:00, тренировка в 12:00. У задачи можно открыть прикреплённые заметки, прикрепить существующую или написать новую. Голос с микрофона превращается через Gemini в редактируемый текст заметки. Исходный аудиофайл хранить не требуется.

## Предлагаемые инженерные решения

Это решения исполнителя, а не дополнительные требования пользователя. Go + Wails v2 + React/TypeScript: Windows x64, обычное окно с панелью задач; WebView2 как зависимость. Из Solveo повторно используются узкие решения захвата микрофона WASAPI, Gemini Transcribe Live и Windows Credential Manager. Сам Solveo не изменяется; пользовательские настройки и ключи не копируются. Только микрофон, без захвата системного звука и Docker.

Календарь строится на поддерживаемом React-компоненте с видами месяца, недели и дня; собственный движок календаря не пишется. Интерфейс русский. Go владеет данными, проверками, хранилищем и голосовой сессией; React отображает состояние и редактирует черновики.

## Заметки и темы

- Тема: название, цвет, отдельный ручной порядок. Есть системная выборка «Все заметки» и заметки без темы. В первой версии у заметки максимум одна тема, вложенных тем нет.
- Заметка: заголовок, текст, выбранная пользователем календарная дата, тема, признак закрепления, ручная позиция, технические даты создания и изменения. Текст обычный; полноценный редактор документов не входит в первую версию.
- Дата заметки — `YYYY-MM-DD`, без времени и пересчёта часового пояса. По умолчанию сегодня, можно менять независимо от времени создания.
- Три режима списка: дата от новых к старым, дата от старых к новым, ручной порядок. Закреплённые заметки идут отдельной верхней группой во всех режимах; внутри групп действует выбранная сортировка. Стабильный дополнительный ключ исключает случайные перестановки при одинаковых датах.
- Темы и заметки можно переставлять вверх/вниз. Перестановка заметок доступна в ручном режиме и сохраняется при переключении сортировки. Поиск по заголовку и тексту, фильтр по теме. Перестановка при активном поиске отключена, чтобы не менять скрытые элементы неожиданным образом.
- Редактирование сохраняется автоматически с короткой задержкой и видимым статусом. При смене заметки/переходе в календарь черновик сначала сохраняется. При ошибке черновик остаётся доступен, ошибка показывается явно; приложение не сообщает об успешном сохранении заранее.
- Удаление с подтверждением; удаление темы сохраняет её заметки без темы. Удаление заметки убирает связи с задачами. Удаление задачи не удаляет заметки.

## Календарь и связи

- Задача: название, начало, конец, описание, цвет, завершённость и список ID заметок. Конец строго позже начала. Задача может пересекать полночь или занимать несколько дней. Пересечения задач допустимы и видны на сетке.
- Виды «Месяц», «Неделя», «День», переход к сегодня, переход по периодам. Неделя начинается с понедельника. Время показывается в локальном часовом поясе Windows; моменты времени сохраняются с явным UTC offset/в UTC. Перенос компьютера в другой часовой пояс меняет отображаемое местное время того же события.
- Щелчок/выделение интервала создаёт задачу; карточка позволяет изменить время, перенести задачу и отметить завершённой. Перетаскивание и изменение длительности сохраняются через Go; при ошибке календарь откатывает изменение.
- В карточке задачи можно выбрать несколько существующих заметок, открепить их или создать новую. Одна заметка может быть связана с несколькими задачами. Для новой заметки по умолчанию берётся местная дата начала задачи; последующие изменения времени задачи не меняют дату заметки.
- Повторяющиеся события, уведомления в фоне, интеграция Google/Outlook и совместная работа не входят в первую версию: пользователь их не запрашивал.

## Голос

- В редакторе заметки кнопка записи, видимый статус, остановка и отмена. Одновременно одна сессия, default microphone Windows.
- Распознанный текст сначала попадает в отдельный черновик. Пользователь явно добавляет результат в выбранную заметку или отменяет; существующий текст не заменяется. Смена текущей заметки не меняет адресата уже начатой записи.
- Сначала завершается отправка аудио и получение последней фразы, затем закрывается соединение. Сетевые ошибки, отсутствие микрофона, доступа к модели или ключа, переполнение очереди показываются пользователю. Нет скрытого повторного подключения и повторной отправки аудио.
- API-ключ вводится в настройках, хранится под отдельным именем Daynote в Windows Credential Manager. Ключ не возвращается в UI, не пишется в базу, журналы, Git или бэкапы. Аудио передаётся Google только после явного запуска записи; текстовые заметки сами по себе туда не отправляются. Интернет нужен только для Gemini.

## Хранение и восстановление

- Рабочая SQLite-база в пользовательском каталоге приложения под `%LOCALAPPDATA%/Daynote`; один экземпляр приложения. Поддерживаемый Go-драйвер, совместимый с Windows-сборкой; SQL-операции только внутри приложения. Транзакции для перестановок, связей и удаления, включённые foreign keys, версия схемы. Повреждённая/неизвестная база не заменяется пустой.
- В настройках выбирается существующая папка OneDrive через системный диалог. Приложение пишет туда отдельные законченные резервные копии в переносимом JSON-формате с версией; рабочую SQLite-базу не копирует на лету.
- Автоматическая копия после изменений с задержкой и объединением частых сохранений; также кнопка «Создать копию». Сначала временный файл, затем переименование. Имя включает время и уникальный суффикс; существующие копии не перезаписываются. Автоматического удаления старых копий нет в первой версии. Ошибка копирования не блокирует локальное сохранение и видна в настройках.
- Наличие файла в локальной папке OneDrive не доказывает завершение облачной загрузки; приложение честно сообщает о создании локальной копии. Выбор папки сам по себе не проверяет, что она обслуживается OneDrive.
- Восстановление через системный выбор JSON, предварительная валидация всего содержимого, подтверждение замены. Перед заменой создаётся локальная аварийная копия; импорт и связи восстанавливаются одной транзакцией. Ключ Gemini и настройки папки бэкапов не импортируются. При ошибке текущие данные остаются неизменными. Пустое первое открытие показывает понятные действия, без вымышленных пользовательских заметок.

## Проверка и поставка

Проверить бизнес-инварианты сортировки/закрепления, сохранение после перезапуска, связи и удаление, календарные интервалы/переход суток, некорректный импорт и восстановление, сбои резервного копирования. Голос проверять fake transport и fake capture без реальных запросов и ключей. Проверить UI-сценарии создания/редактирования заметки и задачи. Сгенерировать Wails bindings штатным генератором, собрать frontend, провести Go tests/vet и Windows x64 build.

В проекте: краткий `AGENTS.md`, README с запуском/сборкой, данными, Gemini, OneDrive и ограничениями; CI с Windows-сборкой и скачиваемым EXE. Публичный репозиторий не содержит заметок, ключей и заимствованных данных Solveo. Публикация исходников и создание репозитория разрешены пользователем; отдельный release не обязателен. Ручной запуск EXE, микрофон и Credential Manager на Windows являются отдельной приёмкой: сборка в WSL их не доказывает.
