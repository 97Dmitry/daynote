# Daynote: фоновая работа, напоминания и релизы

## Подтверждённые требования

Пользователь запросил GitHub Releases, отключение меню перемещения/управления окном по Alt, несколько уведомлений у события (до начала и в конкретное время), звук и индикацию на иконке, трей с сохранением работы после закрытия окна, выход только из трея, опциональный запуск с Windows. Пропущенные напоминания показываются за последние 24 часа после запуска/пробуждения.

## Предлагаемое поведение

- Обычный запуск показывает окно; запуск автозагрузкой `--background` оставляет только иконку трея. При видимом окне остаются обычная кнопка панели задач и Alt+Tab: наличие трея само по себе не требует скрывать приложение из переключателя окон.
- Крестик и Alt+F4 скрывают окно после сохранения текущей заметки; процесс и напоминания остаются активными. Открытые карточки и их черновики сохраняются в renderer. Голос при скрытии останавливается, полученный черновик остаётся доступен, микрофон в фоне не продолжает запись.
- Двойной щелчок по иконке и пункт «Открыть Daynote» показывают/восстанавливают окно. «Выход» в меню трея запрашивает завершение: сохраняется заметка, при открытом модальном черновике требуется подтверждение его отмены. Ошибка сохранения показывает окно и блокирует выход. У ОС сохраняется возможность завершить процесс при выключении Windows.
- При повторном запуске в том же Windows-сеансе открывается уже запущенное окно; автозапуск повторного экземпляра не выводит лишнее сообщение.
- Иконка восстанавливается после перезапуска Explorer. Если создать трей не удалось, приложение показывает ошибку и оставляет доступный выход через окно; оно не должно стать невидимым незавершаемым процессом.
- Alt исправляется узко: блокируется Win32 `WM_SYSCOMMAND/SC_KEYMENU` у окна Daynote. Alt+Tab, другие сочетания и ввод с модификаторами не отключаются глобально.

## Напоминания

- У задачи список напоминаний. Каждое: стабильный ID, режим «до начала» с целым количеством минут (включая 0) либо «в конкретное время» с датой/временем, включённый/отключённый звук. Можно добавлять и удалять строки; по умолчанию при добавлении предлагается 30 минут и звук. Без добавленных строк задача не создаёт напоминаний.
- Относительное напоминание пересчитывается при переносе события; абсолютное сохраняет выбранный момент. Моменты хранятся с явным offset/в UTC, отображаются локально. Завершённые/удалённые задачи не создают новых уведомлений.
- Планировщик работает в Go независимо от видимости окна: сразу после запуска, после изменения данных и раз в несколько секунд. После сна/перезапуска показывает ещё не обработанные напоминания за последние 24 часа; более старые пропускает. Дедупликация учитывает задачу, ID напоминания и рассчитанный момент.
- Системное уведомление Windows показывается через штатную иконку трея (`Shell_NotifyIcon`); звук — системный сигнал. Иконка трея меняется при непрочитанных напоминаниях, tooltip содержит их количество. Видимое окно дополнительно привлекает внимание кнопкой панели задач. Это не обещание доставки звука при выключенном звуке/настройках запрета уведомлений Windows.
- В приложении есть список уведомлений с переходом к задаче, отметкой прочитанного и «Прочитать все». Непрочитанные хранятся между запусками. Одновременно сработавшие напоминания объединяются в один системный сигнал/баннер; отдельные записи остаются в списке.
- Запись уведомления фиксируется локально до обращения к оболочке Windows, чтобы не повторять звук после каждого перезапуска. При ошибке системного показа сохраняются запись и индикатор, ошибка видна пользователю. Авария между фиксацией и вызовом Windows может оставить только запись в списке; exactly-once показ внешней оболочки не обещается.

## Хранение и совместимость

- Напоминания являются частью задачи и включаются в JSON-бэкап. Schema/backup version повышается до 2: старые базы безопасно мигрируются приложением, старые JSON v1 читаются без напоминаний. Неизвестные будущие версии отклоняются. Старое приложение не должно открывать обновлённую базу и молча стирать новые поля.
- Локальная таблица фактов уведомлений обеспечивает дедупликацию и список прочитанного/непрочитанного. Она не экспортируется в OneDrive. Удаление задачи убирает её уведомления; восстановление бэкапа сбрасывает локальные факты уведомлений и применяет правило пропуска/доставки за 24 часа.
- Settings-сохранение остаётся атомарным и не затирает тему/путь бэкапов. Прямых административных изменений пользовательской базы из агентской сессии нет: миграция и работа с данными выполняются кодом приложения.

## Автозапуск

- Выключен по умолчанию, включается пользователем в настройках. Приложение пишет только своё значение `Daynote` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: полный кавыченный путь текущего EXE и `--background`; администраторские права не требуются.
- Состояние читается из Windows, а не дублируется неподтверждённым флагом в JSON. После перемещения EXE пользователь может обновить путь повторным включением. Приложение не переопределяет запрет автозапуска в системных настройках Windows.

## Releases

- Существующие проверки сохраняются. После успешных Go/frontend/browser/Windows checks на `main` отдельный job скачивает ровно проверенный artifact по ID и сверяет SHA-256; EXE не пересобирается.
- Публикация `build-N` содержит `Daynote.exe`, полный ZIP с notices/документацией и `SHA256SUMS.txt`. Загрузка идёт в draft; публичным релиз становится только после успешной загрузки. Повторный запуск сохраняет уже опубликованные assets, несовпадающий commit/ошибка API/неверный checksum останавливают публикацию. Устаревший commit не перезаписывает Latest.
- README ведёт на Releases/latest. Реальный релиз и скачанные assets проверяются после завершения workflow.

## Проверки и границы

Регрессии: относительные/абсолютные/несколько напоминаний, 24-часовой catch-up, дедупликация после перезапуска, перенос/удаление/завершение события, совместимость v1 и атомарный импорт, сохранение перед hide/quit, отказ сохранения, настройки автозапуска с пробелами в пути, предикат Alt, fake-shell уведомления и fake-gh публикация. Browser проверяет формы и список уведомлений. CI запускает Windows-only тесты и сборку.

В WSL нельзя считать подтверждёнными настоящий tray/Alt, Explorer restart, звук, уведомления, Windows sign-in и titlebar/taskbar behavior. Они отдельно перечисляются в ручной Windows-приёмке. Нового сервиса, Windows Service, облачного планировщика и запуска выключенного ПК не добавляется.
