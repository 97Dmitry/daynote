# Daynote: повторяющиеся задачи

Статус: согласовано пользователем; реализовано, автоматические проверки пройдены. Windows runtime-приёмка отдельно.

## Задача и подтверждённый объём

Пользователь хочет создавать задачи на каждый день, выбранные дни недели,
будни и выходные. Отдельно подтверждены исключения: перенос или удаление
одного повторения. Выполнение отмечается отдельно для каждого дня.

Текущая задача содержит один абсолютный интервал и один `done`. Простое
добавление дней недели к форме недостаточно: выполнение не должно завершать
всю серию, а напоминания должны работать и при скрытом окне.

Остаются Go/Wails v2, React и существующий FullCalendar. Новая библиотека
повторений, облачный сервис и фоновое создание бесконечных копий не нужны.

## Предлагаемое поведение

Следующие детали — решения исполнителя, предлагаемые пользователю вместе
с подтверждённым объёмом выше.

- В карточке задачи поле «Повторять»: «Не повторять» (по умолчанию), «Каждый
  день», «По будням», «По выходным», «Выбранные дни». Для последнего — семь
  переключателей Пн–Вс, выбран хотя бы один. Будни — Пн–Пт, выходные — Сб–Вс;
  производственный календарь и государственные праздники не учитываются.
- Начальная дата ограничивает серию снизу; первый экземпляр появляется в
  первый выбранный день начиная с этой даты. Можно указать включительную
  дату окончания; по умолчанию серия не ограничена.
- Повторяется местное время начала в часовом поясе создания серии. Часовой
  пояс IANA берётся у renderer, проверяется и сохраняется Go; в форме серии
  показано его название. При смене часового пояса компьютера серия остаётся
  привязана к исходному поясу, календарь показывает соответствующее местное
  время компьютера. Одноразовые задачи сохраняют прежнюю семантику instants.
- Длительность серии — исходная абсолютная длительность задачи. Задачи
  через полночь и многодневные интервалы поддерживаются. При смене сезонного
  времени местное начало сохраняется, местный конец может сместиться.
- Если местное время начала не существует при переходе на летнее время,
  только этот экземпляр пропускается. При двукратном времени используется
  первый момент. Это правило применяется одинаково в календаре и reminders;
  нельзя полагаться на неявную нормализацию `time.Date`.
- Отметка «Выполнено» относится только к открытому повторению; её можно
  снять. Остальные дни и их напоминания не меняются. Пропущенные задачи не
  становятся автоматически выполненными и не переносятся на сегодня.

## Редактирование и исключения

- Клик по повторению открывает карточку с его датой, отметкой выполнения,
  временем и действиями «Изменить серию», «Удалить это повторение»,
  «Удалить серию». В карточке повторения можно изменить его интервал;
  название, описание, цвет, заметки и правило напоминаний меняются в серии.
  Для разовой задачи остаётся прежняя форма.
- Перетаскивание или растягивание повторения меняет только этот экземпляр.
  Сохраняется исходная дата экземпляра даже при переносе на другой день.
  Ошибка сохранения откатывает календарное действие.
- Удаление одного повторения сохраняет исключение «пропущено»; задача не
  возникает снова после перезапуска или переключения периода. В редакторе
  серии доступен список исключений с исходной датой и действием «Сбросить»:
  для переноса/удаления возвращается обычное повторение, для выполнения
  снимается отметка. Сброс всего исключения явно подтверждается, если он
  одновременно убирает перенос и выполнение.
- Изменение серии применяется ко всему расписанию, включая прошлые даты.
  Отдельного режима «этот и последующие» в этом изменении нет. Это явно
  написано в редакторе серии. Исключения привязаны к исходной дате: переносы
  сохраняют свои абсолютные интервалы, выполнение и удаления сохраняются.
  Если дата перестаёт входить в правило, соответствующее исключение
  удаляется атомарно с сохранением серии после подтверждения с количеством
  затронутых исключений. Скрытых неактивных исключений не остаётся.
- Включение повторения у разовой задачи создаёт серию без исключений;
  старый `done` не переносится на всю серию, форма предупреждает о сбросе.
  Отключение повторения в редакторе серии оставляет одну разовую задачу
  с исходным интервалом серии, очищает исключения и требует подтверждения.
- Удаление серии требует подтверждения, убирает все её экземпляры и
  локальные уведомления. Заметки остаются; все экземпляры серии используют
  общие связи с заметками, без копирования текстов.

## Данные и границы Go/renderer

- У задачи необязательное правило: набор уникальных дней недели,
  IANA timezone и необязательная конечная дата. UI-пресеты нормализуются
  в набор дней: отдельные флаги для будней/выходных не хранятся.
- Исключения — отдельные компактные записи внутри серии, ключом служит
  исходная календарная дата в поясе серии, значением — `done`, `skipped`
  и необязательный заменяющий интервал. Бесконечная серия не порождает
  заранее записи. Накопленные исключения не удаляются по таймеру.
- Для серии общий `done` всегда false. Go проверяет даты, timezone,
  непустой набор дней, принадлежность ключей правилу, уникальность ключей,
  интервалы и отсутствие несовместимых полей. Все операции атомарны и
  сохраняют существующие правила clone/validate/transaction/swap.
- IANA timezone data встраиваются в Go-бинарник через `time/tzdata`, чтобы
  Windows-сборка не зависела от наличия внешней базы часовых поясов.
- Один Go-механизм вычисляет экземпляры для календаря и напоминаний.
  Renderer запрашивает пересекающие видимый полуоткрытый интервал
  экземпляры через API. Ответ содержит ID серии, исходную дату,
  эффективные start/end и done. Renderer не вычисляет повторения сам.
- Ключ экземпляра стабилен: ID серии + исходная дата. Разовые задачи
  сохраняют свой ID. В выборку входят многодневные пересечения и перенесённые
  исключения с исходной датой за пределами видимого периода. Даты вне
  диапазона не разворачиваются от начала всей истории.
- При переключении календаря устаревший ответ не перезаписывает новый;
  после сохранения загружается актуальный видимый период. Ошибки видимы,
  черновик не теряется. Редактирование повторения не отправляет его
  вычисленный интервал как новый исходный интервал всей серии.
- Валидация API ограничивает запрос календаря максимумом 366 дней;
  слишком большой диапазон отклоняется явно, без усечения результатов.

## Напоминания и список уведомлений

- Относительные напоминания вычисляются от эффективного начала каждого
  экземпляра, включая переносы. Выполненные/пропущенные экземпляры не
  создают новых уведомлений. Уже доставленные записи не отзываются.
- Для серии существующий режим «в конкретное время» означает тот же
  календарный сдвиг от исходной даты и местное время в поясе серии.
  Например, напоминание в 18:00 накануне повторяется накануне каждого
  экземпляра. Форма показывает эту семантику. Перенос одного экземпляра
  сдвигает относительные напоминания, но сохраняет вычисленное для исходной
  даты календарное напоминание «в конкретное время», как у разовой задачи.
  Если время такого напоминания не существует при DST, оно пропускается;
  при двукратном времени используется первый момент.
- Планировщик сохраняет 24-часовое окно и работает без renderer. Для
  каждого напоминания вычисляет обратный диапазон дат экземпляров,
  соответствующий окну due, с проверкой эффективных моментов и исключений.
  Большой offset не приводит к сканированию от начала серии и не теряет
  уведомления о далёких будущих/прошлых экземплярах.
- Ключ дедупликации серии включает ID серии, исходную дату, ID напоминания
  и вычисленный UTC due. Для разовых задач сохраняется существующий ключ,
  чтобы миграция не повторяла уже обработанные уведомления.
- В локальном receipt хранится исходная дата экземпляра. Переход из inbox
  открывает соответствующее повторение, включая перенесённое. Если оно
  уже удалено или исключено новым правилом, UI сообщает об этом и предлагает
  открыть серию; не открывает молча другой день.
- Запись receipt до shell delivery, звук, агрегация, unread и очистка
  runtime receipts при restore сохраняют существующие правила.

## Совместимость и проверки

- Версия SQLite и backup повышается до 3. Миграция выполняется кодом
  приложения; задачи v1/v2 становятся разовыми без изменений времени,
  выполнения, заметок и напоминаний. Старые receipts сохраняются. Backup
  v1/v2 принимаются, неизвестные будущие версии отклоняются.
- Правила и исключения включаются в backup; receipts по-прежнему нет.
  Restore валидирует весь граф до замены. Агент не изменяет пользовательскую
  базу напрямую; проверки используют временные тестовые базы.
- Go-тесты: все пресеты, границы начала/окончания, leap day и смена года,
  timezone/DST, интервалы через полночь, многодневные пересечения,
  выполнение/отмена, перенос с исходной датой вне выборки, удаление/сброс,
  изменение правила с исключениями, миграция/backup/reopen, reminders с
  большими offsets, дедупликация и работа без renderer.
- UI-тесты: создание каждого режима, выбор дней и даты окончания,
  независимое выполнение дней, перенос/удаление одного экземпляра,
  редактор серии и подтверждения, переход из уведомления, ошибка API
  с сохранением черновика/откатом и защита от устаревшего ответа периода.
- `make bindings`, `make check` и существующие browser checks обязательны.
  Реальные Windows tray/звук и работа после сна остаются отдельной ручной
  приёмкой; сборка в WSL не доказывает их.

## Не входит в изменение

Производственный календарь, праздники, интервалы «раз в N недель»,
месячные правила, количество повторений вместо конечной даты, отдельные
названия/заметки/напоминания одного дня, режим «этот и последующие»,
внешняя календарная синхронизация и удаление истории по сроку.

Размещение типов, сигнатуры API и разделение файлов определяются планом
реализации в пределах существующей архитектуры; новый общий фреймворк
расписаний не нужен.
